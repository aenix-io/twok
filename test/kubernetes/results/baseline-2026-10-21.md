# Kubernetes bench, baseline with plain etcd, 2026-10-21

Raw records of the runs summarised in [docs/testing.md](../../../docs/testing.md#kubernetes-test-bench).
Each record is the file the harness writes to `TWOK_RESULTS`; only the repeated Cilium deny verdicts are cut short.
No secrets appear in them: the bench uses plain HTTP and no credentials.

## Environment

- Cluster: five Talos v1.12.0 nodes, Kubernetes v1.33.1, containerd 2.1.6, Cilium 1.19.5 with kube-proxy replacement and `enable-policy=default`, the NFS CSI driver as the default StorageClass.
- etcd: `gcr.io/etcd-development/etcd:v3.6.15` by digest `sha256:5ed4e32061aa061f970d6500629213e8579ef17571dcf9789074966acb9afad1`, default heartbeat (100 ms) and election timeout (1000 ms).
- Members: the StatefulSet of `deploy/kubernetes/base` without the twok sidecar (`test/kubernetes/manifests/baseline`), etcd-0 on node3 and etcd-1 on node1.
- Writers: one per member, on the member's node, `etcdctl put` to its own member only with 1 s dial and command timeouts, one put every 0.2 s plus the put's duration.
- Partition: `test/kubernetes/manifests/partition.yaml` (both directions) or `partition-one-way.yaml`, for 60 s.

## Commands

```bash
export K8S_KUBECONFIG=<kubeconfig of the test cluster>
hack/kubernetes-bench.sh TestPartition
hack/kubernetes-bench.sh TestPartitionOneWay
```

The first run used an earlier layout of the same StatefulSet (data directory `/var/lib/etcd/data`) and watched only 30 s after the heal; the pair had not recovered by then, which is why the harness now waits for the recovery and reports when it happens.

## A policy on statefulset.kubernetes.io/pod-name selects nothing

Before the runs, a CiliumNetworkPolicy with `endpointSelector: {matchLabels: {statefulset.kubernetes.io/pod-name: etcd-0}}` and the same deny rules was applied.
The Cilium identity of both members was the same and had no pod-name label, and the agent on etcd-0's node reported no enforcement:

```text
$ kubectl get ciliumendpoint -n twok-test etcd-0 -o json | jq '.status.identity'
{"id": 43710, "labels": ["k8s:app.kubernetes.io/name=etcd", "k8s:app.kubernetes.io/part-of=twok",
  "k8s:io.cilium.k8s.namespace.labels.kubernetes.io/metadata.name=twok-test", ..., "k8s:io.kubernetes.pod.namespace=twok-test"]}
$ kubectl exec -n cozy-cilium cilium-zqvxn -c cilium-agent -- cilium-dbg endpoint list | grep ^1742
1742       Disabled           Disabled          43710      k8s:app.kubernetes.io/name=etcd   10.244.2.236   ready
```

With the label `twok.aenix.io/member` put on the Pods by the harness, each member got its own identity about 10 to 25 s after the label, and the same agent reported `Enabled Enabled` for etcd-0 once the partition was applied (see the records).
